# 大盘双名单选股（可移植版）

一份 **零第三方依赖** 的选股脚本。根据大盘涨跌，输出两份名单：

- **【A】跌日·防御名单** —— 活跃度最低的一批（低弹性、低波动、低成交额、未创新低）
- **【B】涨日·进攻名单** —— 活跃度最高的一批（高弹性、高波动、高成交额、创新低）

> **先说清楚它能做什么、不能做什么**
> 它判定的是「**到现在为止**大盘涨了还是跌了」，**不是预测明天**。
> 历史回测（2025-10~2026-10，3017 只 × 243 个交易日）：即使完美预知大盘涨跌，
> 加权红盘率上限也只有 **51.46%**（随机买入是 46.49%，仅高 4.97pp）。
> 在真实「不知道明天大盘」的情况下，能拿到的只有 **+0.91pp**。
> **名单只是排序结果，不是买卖指令。**

## 一、环境要求

| 项目 | 要求 | 说明 |

```bash
curl -s "https://qt.gtimg.cn/q=sh000001"
```

能返回一串带 `~` 分隔的数据就 OK。

## 二、快速开始

### 1. 把整个文件夹拷到目标电脑

七个 `.py` 文件必须放在**同一个目录**，`pool.txt` 也必须在这个目录。

### 2. 改票池（可选）

编辑 `pool.txt`，每行一只股票：

```
# 井号开头是注释，空行忽略
sh600519   贵州茅台
sz000001   平安银行
600036     招商银行      ← 纯数字也行，6 开头自动判为 sh
```

代码前缀规则：

- `sh` = 上交所：6 开头（主板）、688 开头（科创板）
- `sz` = 深交所：00 开头（主板）、30 开头（创业板）

### 3. 运行

```bash
python3 scan_macd.py --dual
```

macOS / Linux 也可以直接双击 `run_dual.sh`，Windows 双击 `run_dual.bat`。

想用命令行直接临时查几只（不读票池）：

```bash
python3 scan_macd.py 600519 000001 300750 --dual
```

## 四、选股逻辑是怎么来的

1. 对 15 个候选因子逐个做**分位单调性检验**，只保留在跌日/涨日两个场景下
   **都单调、且方向相反（镜像）** 的因子 → 只剩 4 个：`beta60 / vol20 / amt20 / newlow20`
2. 这 4 个本质上是同一根轴（**活跃度 / 风险**）的四个测度，**不是四个独立 alpha**
3. 各自标准化后等权合成为 `act`，**两端各取一份名单**
4. 隔夜质量过滤：近 5 日「低开 ≤ −1%」达 2 次以上，或有一次跳空 ≤ −3% 且当天没摸回昨收 → **直接剔除**
   （实测：这类票次日跳空 ≤ −1% 占 24.2%，通过筛选的只有 8.2%；T收→T+1收 差 +0.19%/天，t=5.0）
5. 大盘状态由上证指数实时涨跌幅判定：涨 ≥ +0.5% 倾向进攻名单、跌 ≤ −0.5% 倾向防御名单、中间为「平淡日」
5. **（2026-11-02 新增）日K趋势优先层**：活跃度只回答「弹性大不大」，不管方向。
   所以先按「日线在涨吗」分三级，再在同级里按 `act` 取两端：

   | 级别 | 档位 | 判定 |
   |---|---|---|
   | 1 | ✦刚金叉 / ↑上涨 | 金叉（近5根内 DIF 上穿 DEA 或柱翻正）**且**趋势分≥2 ／ 趋势分≥3 |
   | 2 | →横盘 / ✦金叉·仍弱 | 趋势分=2 ／ 有金叉但趋势分≤1（多是下跌途中反抽） |
   | 3 | ↓下坡 | 趋势分≤1 且无金叉 |

   趋势分（0~4）= 站上MA20 + MA10上行 + 5日涨幅>0 + 10日涨幅>0，各 1 分。
   名单顺序 = 1 级优先 → 不够才补 2 级 → 再不够才用 3 级（同级内按 `act` 取两端）。

   ⚠️ 第一版只判「柱翻正 ≤2 根」就算金叉，实测 8 只金叉票有 6 只 5 日涨幅 −6%~−16%
   —— 那是深水下跌途中的反抽，不是启动。所以金叉必须叠加趋势分。

**为什么两份名单都不用 MACD 做门槛？**
实测发现 `DIF<0 水下 + 缩量` 筛出的恰恰是**低活跃度**票，与「涨日要买高活跃」直接冲突。
所以 MACD 降级为展示列，你可以自己看，但脚本不会因为它过滤掉任何票。

## 五、参数速查

| 参数 | 作用 |
|---|---|
| `--dual` | **必须**。输出双名单（不加则走原来的单名单模式） |
| `--json` | 同时写出 `dual_picks.json`，供网页/其他程序读取 |
| `--all` | 打印全部通过标的，不只看 Top8 |
| `--old` | 关闭大盘 KDJ 门控（本移植版本来就没有该模块） |

单次运行约 **10 秒**（40 只票口径），数据来自腾讯，全栏目均为**盘中实时**。

## 七、常见问题

**Q：提示「没有指定代码，也没读到票池」**
检查 `pool.txt` 是否和 `.py` 在同一目录，且没有被注释符号 `#` 全遮住。

**Q：Windows 下中文乱码**
在命令行先执行 `chcp 65001` 切到 UTF-8，再运行脚本。

**Q：提示「大盘30分KDJ门控：⚠️ 大盘取数异常: No module named 'index_kdj_watch'」**
**这是正常的，不影响使用。** 原版脚本的大盘 KDJ 门槛依赖 `index_kdj_watch` 模块，
该模块会读写 GitHub 云端状态，移植版刻意不带。双名单逻辑不依赖它，看到这行提示忽略即可。

**Q：返回空名单 / 票全被过滤掉**
名单要同时满足两条：**通过可买性检查**（`filt` 为空）+ **近期无除权**（`dividend` 为空）。
常见拦截原因：

| 被拦原因 | 说明 |
|---|---|
| `换手0.5%` / `换手1.0%` | 换手率太低，流动性不足，买进去难出货 |
| `成交额` 过低 | 同上 |
| 近期有除权日期 | 行情数据**未复权**，除权会造成「假跌/假新低」，必须剔掉 |
| 涨停 / 一字板 / ST / 次新 | 买到概率极低或风险不可控 |

实盘很常见：**约 65% 的交易日选不出票是正常的**，别为了凑名单放宽条件。

不确定某只票为何被拦？用它单独跑一次，看页面顶部的体检详情：

```bash
python3 scan_macd.py 600519 --dual
```

**Q：能改成穿代理跑吗？**
脚本内部已强制清除 `http_proxy` 等代理环境变量（避免本机代理污染行情数据）。
如果公司网络必须走代理，需要改 `scan_newlow.py` 的 `curl()` 加 `--proxy` 参数。
